# pixie-quest V28 改造计划 — 真实可用与教学闭环

> 前置结论：V27 的 25/25 PASS 不成立；UI-09、UI-10、UI-13 证据失效。真实 LM Studio 与真人教学效果尚未验收。
> 版本目标：关闭虚假通过和不可见功能，完成真实模型验收，再交付错因诊断、学习者摘要、答后讲解。
> 核心原则：功能完成、管线完成、真实模型完成、教学有效是四个不同结论，分别提供证据，不得互相替代。

## 1. 范围与优先级

| 批次 | 内容 | 优先级 | 发布门槛 |
|---|---|---|---|
| A. 可信基线 | 修复地图弹窗；修正可见性断言；重跑核心回归 | P0 | 必须全部通过 |
| B. 真实模型 | 使用约定的真实 LM Studio 模型复测协议、质量、降级和延迟 | P0 | 必须全部通过；失败则保持静态降级，不宣称 LLM 验收完成 |
| C. 教学闭环 | 错因诊断、学习者摘要、L4 答后讲解、复习入口 | P1 | 功能与安全指标全部通过 |
| D. 教学研究 | 真人三组对照、延迟复习效果 | P2 | 单独出研究报告，不阻塞无 LLM 核心版本 |

本版不做离线题目自动生产、复杂人设和精灵解说合并，避免扩大范围。

## 2. 批次 A：可信基线

### A1. 弹窗修复

- 将 `#wbwrap`、`#flwrap` 移出隐藏的 `#gamescreen`，放到页面顶层。
- 地图页打开后，弹窗真实可见、内容正确、可点击关闭；关闭后不可见。
- 回归战斗页入口、导出、清空、Esc/遮罩（若已有）行为，不改变既有数据逻辑。

### A2. 验收驱动修复

- 新增统一可见性断言：计算样式、全部祖先、`getBoundingClientRect`、视口范围、中心点命中。
- PASS 必须同时满足状态、内容和真实可见性；仅检查 `.show` 不算通过。
- 截图在断言通过时即时生成，写入本次唯一验收目录；记录 commit、时间、命令、退出码和证据 SHA-256。
- 报告只根据本次机器结果生成；BLOCKED 不得写成 PASS，环境描述从实际探测结果生成。

### A3. 必过回归

- `npm test`、`npm run check`、`npm run audit` 退出码均为 0。
- UI-01～13 重跑；UI-08 必须使用真实冰霜魔王，不允许给 Grass Slime 注入技能代替。
- 无 LLM 时，地图、答题、结算、错题本、精灵日志完整可玩。

## 3. 批次 B：真实 LM Studio 验收

- 记录实际模型 ID、服务地址、模型加载状态和参数；不得使用 mock 数据补齐缺失指标。
- 固定题库分层抽样，保留每个样本的原始请求、原始响应、最终展示、延迟和降级原因。
- 分开统计 `rawStructuredJsonRate` 与 `finalOutputComplianceRate`。
- 语言质量采用人工盲评，至少两名评审；分歧样本复核，保留逐条判定。
- 真实服务不可用则该项为 BLOCKED；静态模式仍可验收，但版本不得标记“真实 LLM 已通过”。

建议真实模型初始门槛（正式执行时不得事后放宽）：

| 指标 | 门槛 |
|---|---|
| 样本量 | 不少于 120 条，覆盖 L1/L2/L3 和各知识点 |
| 答前泄题 | 0；展示文本与原始输出均检查 |
| 非法输出安全降级率、不可用降级率 | 100% |
| 最终输出合规率 | ≥99% |
| 题目匹配率、教学事实准确率 | ≥98%、≥95% |
| 人工语言质量 | 合格率 ≥95%，无严重误导 |
| 延迟 | 报告 p50/p95/max 和超时率；p95 ≤3s，超时率 ≤1% |

## 4. 批次 C：教学闭环

### C1. 错因诊断

- 由题目、正确项、所选错误项和知识点生成受限类别：三形混淆、句型误判、词义不清、拼写混淆、未知。
- 游戏侧校验类别与题目是否兼容；证据不足时使用“未知”，不得强行推断。
- 诊断只决定提示策略，不能直接泄露答案。

### C2. 学习者摘要

- 填充 `recentWeaknesses`、`masteredRecently`，仅发送当前题目所需的最小结构化摘要。
- 掌握度来自可重算历史：首答、重试、复习结果；不得由模型自行声明。
- 提供清空记录后的行为验证，确保旧画像不串入新学习者。

### C3. L4 答后讲解

- 作答结算前仅允许 L1～L3；结算后才允许 L4 和正确答案。
- 优先展示题库已审计的 `explanation`，LLM 只做受控补充。
- 答错重试时不能提前出现完整解析；换题后不得显示上一题讲解。

### C4. 延迟复习

- 错题本增加“复习”入口，按知识点和过去错误生成复习队列。
- 分开记录首答、提示后重试和延迟复习，不能合并成同一个正确率。
- 首版复习采用本地规则，不依赖 LLM。

## 5. 必须提交的验收结果

每个用例提供：`id / commit / environment / command / expected / actual / status / metrics / evidencePaths`。状态只能是 PASS、FAIL、BLOCKED。

1. **命令原始日志**：完整命令、退出码、测试总数/通过/失败，不只提交摘要。
2. **真实 UI 证据**：原始驱动结果、可见性数值、弹窗打开截图、真实冰霜魔王截图、控制台错误数。
3. **真实模型样本**：模型信息、120 条以上明细、原始响应、人工质量评分、延迟分布；明确 `mock=false`。
4. **教学功能数据**：错因混淆矩阵、画像上下文样例、L4 阶段隔离检查、首答/重试/延迟复习分指标。
5. **证据清单**：所有文件 SHA-256；截图不得与旧包相同，除非该用例明确标记为复用且不能作为新通过证据。
6. **范围结论**：分别声明核心功能、mock 管线、真实模型、模拟教学实验、真人教学实验是否完成。

## 6. 完成定义

V28 功能版本可发布的必要条件：

- 批次 A 全部 PASS，旧假阳性用例由新证据关闭。
- 批次 B 全部 PASS，或明确裁剪 LLM 声明并只发布静态模式；不得用 mock 冒充真实模型。
- 批次 C 全部 PASS，无 P0/P1 未关闭缺陷。
- 报告结论可由原始结果重算，证据环境与内容一致。

“教学有效”不属于上述功能完成的自动推论。只有真人实验达到预先登记的样本量、分组和统计标准后，才能单独声明教学效果。

## 7. 实施顺序

1. 修复弹窗与验收驱动，先得到可信的 13 项 UI 基线。
2. 接通真实 LM Studio，冻结门槛并执行真实模型验收。
3. 依次实现错因诊断、学习者摘要、L4 和复习队列，每项同步补已有测试体系中的测试。
4. 全量回归并生成不可复用旧证据的新验收包。
5. 功能版本发布后，再组织真人三组实验和延迟复习研究。
